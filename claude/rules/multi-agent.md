# 并行与多代理

后台运行、完成通知、续接（`SendMessage`）、停止（`TaskStop`）、写隔离（`isolation: "worktree"`）都由 Claude Code 原生处理，这里只定策略。

- 只在子任务互相独立、各自产出不同证据或交付物、并行收益高于协调成本时委派。优先委派只读探索、测试、日志分析、资料核验和独立 review；小任务主代理直接做。
- 单波最多 5 个 agent，同一条消息内发出。并行写入最多 2 个，必须用 `isolation: "worktree"`，且文件和模块边界互不重叠；共享文件、集成、敏感操作和最终验证由主代理负责。
- 手动开的 `git worktree`（含 `.claude/worktrees/*` 和仓库旁的副本）用完即删：分支合并或放弃后，同一会话内用 `git worktree remove` 移除、确认可达后删掉临时分支，再 `git worktree list` 确认只剩主副本，才算任务完成。worktree 自带 `node_modules`、打包产物等忽略目录，忘删一个就是几个 GB。
- 子任务 prompt 写清范围、边界、验收标准和返回格式，只传最小必要上下文。需要继承完整上下文时用 `fork`，否则选合适的专项类型。
- 派出后主代理继续做不依赖结果的工作，靠完成通知收口，不轮询、不猜测未返回的结果。
- Review finding 不等于实现授权。收口时分为 `accepted`（原范围内且影响验收，或有正确性/安全/数据损失证据）、`deferred`（有效但超范围）、`dismissed`（无证据或违背已验证事实）；只有 `accepted` 进入实现，实质扩展先问我。
- 子代理不再递归委派。只有实际成功启动的 agent 才能报告为"已启用"；启动失败就转为主代理串行执行并说明原因。
- `Workflow` 多代理编排仍需我明确要求才用。
