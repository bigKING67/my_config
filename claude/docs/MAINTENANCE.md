# CCG 文档维护指南

> 版本: 1.0 | 最后更新: 2026-02-10

---

## 🔀 两种维护模式

### 模式 1️⃣：简单同步（Simple Sync）

**适用场景**：工具变更时（CCG/Skills/MCP）

**操作范围**：
- ✅ 更新索引（第 8.1/8.2 节）
- ✅ 更新路由表（第 3 章）
- ✅ 更新工具策略（第 4.1 节，仅 MCP）
- ❌ **不改变**核心原则、质量门禁等

**触发频率**：每次工具变更

**触发命令**：
```
"CCG 更新了，请帮我同步 CLAUDE.md"
"我安装/删除了 skill: xxx，请帮我同步 CLAUDE.md"
"我添加/删除了 MCP: xxx，请帮我同步 CLAUDE.md"
```

**Claude 会自动**：
1. 检测变化（读取 config.toml、扫描 skills/、读取 MCP 配置）
2. 生成同步报告（需要添加/删除的项目）
3. 更新 CLAUDE.md（索引和路由表）
4. 验证同步（长度、语法）

**特点**：快速（1-2 分钟）、无副作用、仅更新受影响的章节

---

### 模式 2️⃣：智能优化（Smart Optimize）

**适用场景**：发现 CLAUDE.md 存在问题时

**操作范围**：
- ✅ 调整章节结构
- ✅ 删除冗余内容
- ✅ 修复策略冲突
- ✅ 优化决策树
- ✅ 改进引用方式
- ✅ 重新组织内容

**触发频率**：每月 1 次或发现问题时

**触发命令**：
```
"请帮我做一次 CLAUDE.md 月度审计"
"CLAUDE.md 感觉需要优化下"
"请检查 CLAUDE.md 是否需要优化调整"
```

**Claude 会做**：
1. 全面扫描（workflows、skills、MCP、长度、重复、冲突）
2. 生成问题诊断报告
3. 提出优化建议
4. **等待你确认方案**
5. 执行优化并验证

**特点**：深度分析（5-15 分钟）、需要确认、可能重构多个章节

## 📊 模式选择指南

| 场景 | 推荐模式 | 命令 |
|------|---------|------|
| **新增 workflow** | 简单同步 | `CCG 更新了，请帮我同步 CLAUDE.md` |
| **删除 skill** | 简单同步 | `我删除了 skill: xxx，请帮我同步 CLAUDE.md` |
| **添加 MCP** | 简单同步 | `我添加了 MCP: xxx，请帮我同步 CLAUDE.md` |
| **长度超 380 行** | 智能优化 | `CLAUDE.md 超长了，帮我优化下` |
| **内容感觉混乱** | 智能优化 | `CLAUDE.md 感觉需要优化` |
| **每月定期检查** | 智能优化 | `请做一次月度审计` |

**核心原则**：
> **工具变更 = 简单同步（快速更新索引）**
> **文档问题 = 智能优化（深度重构调整）**

## 📚 文档分层说明

CCG 采用**三层架构**管理文档：

| 层级 | 位置 | 职责 | 长度约束 |
|------|------|------|----------|
| **治理层** | `~/.claude/CLAUDE.md` | 方向、原则、路由、门禁 | 220-380 行 |
| **路由层** | `~/.claude/.ccg/config.toml` | Workflow 清单、路由配置 | 配置文件 |
| **执行层** | `~/.claude/commands/ccg/*.md`<br>`~/.claude/skills/*/` | 详细步骤、参数、示例 | 不限 |

**核心原则**：
- 治理层只保留"为什么"和"何时"
- 路由层是单一事实源
- 执行层保留"怎么做"

## 🔄 更新流程

### 场景 1：新增 Workflow

**触发条件**：安装了新的 ccg workflow

**更新步骤**：
1. 更新 `config.toml` 的 `installed` 列表
2. 创建 `commands/ccg/<workflow>.md`（使用模板）
3. 更新 `CLAUDE.md` 第 3 章路由表：
   - 探索式 → 3.1 节
   - 追溯式 → 3.2 节
   - 团队式 → 3.3 节
   - 工具类 → 3.4 节
4. 更新 `CLAUDE.md` 第 8.1 节索引

**禁止**：
- ❌ 在 `CLAUDE.md` 中写执行细节
- ❌ 在 `CLAUDE.md` 中写 Shell 命令示例

---

### 场景 2：更新已有 Workflow

**触发条件**：workflow 逻辑变更

**更新步骤**：
1. 只修改 `commands/ccg/<workflow>.md`
2. 如果触发场景变化 → 更新 `CLAUDE.md` 第 3 章对应表格的"关键词"列
3. 如果工作流类型变化 → 移动到正确的章节表格

**禁止**：
- ❌ 在 `CLAUDE.md` 中添加详细步骤

---

### 场景 3：调整核心原则

**触发条件**：发现新的通用约束或红线

**更新步骤**：
1. 更新 `CLAUDE.md` 第 2 章
2. 评估影响范围：是否需要同步更新 `commands/ccg/*.md`
3. 记录变更原因和日期

**审批**：
- ⚠️ 核心原则变更需要用户确认（影响全局行为）

---

### 场景 4：工具策略调整

**触发条件**：新增 MCP 服务、工具失效、优先级变化

**更新步骤**：
1. 更新 `CLAUDE.md` 第 4 章工具策略
2. 保持三段式结构（主 + 备选 + 降级）
3. 更新示例（如果有）

**禁止**：
- ❌ 添加工具 API 详细参数（应引用官方文档）

## 🚨 变更门禁

### 允许变更（绿灯）✅

**治理层（CLAUDE.md）**：
- 核心原则（第 2 章）
- 工作流路由表（第 3 章）
- 工具策略（第 4 章）
- 质量门禁（第 5 章）
- 协作边界（第 6 章）
- 例外处理（第 7 章）
- 索引（第 8 章）

**路由层（config.toml）**：
- `installed` 列表
- 路由配置

**执行层（commands/skills）**：
- 详细步骤
- 参数说明
- Shell 命令示例
- ASCII 流程图（在执行层可以有）

---

### 禁止变更（红灯）❌

**治理层（CLAUDE.md）**：
- ❌ 详细执行步骤
- ❌ Shell 命令示例
- ❌ ASCII 流程图
- ❌ 环境配置教程（如 macOS/uv/Python）
- ❌ 具体参数说明
- ❌ 配置文件语法

**理由**：治理层只保留方向和规范，细节会导致：
1. 文档膨胀（难以维护）
2. 重复（与执行层冲突）
3. 漂移（修改一处忘记另一处）

---

### 谨慎变更（黄灯）⚠️

**治理层（CLAUDE.md）**：
- ⚠️ 快速决策树（第 3.5 节）- 需经过场景演练验证
- ⚠️ 启发式规则（第 4.1 节）- 需确保不与 MCP 实际能力冲突

**操作指南**：
1. 变更前：运行场景演练（见审计模板）
2. 变更后：三轮验证（结构 + 一致性 + 场景）
3. 变更时：更新"最后更新"日期

## 📏 长度预算

### 治理层（CLAUDE.md）

**目标长度**：220-280 行（理想）
**允许范围**：220-380 行（可接受）
**当前长度**：366 行 ✅

**超预算触发**：> 380 行
**应对措施**：
1. 检查是否有执行细节混入 → 移至 commands/
2. 检查是否有重复内容 → 合并或删除
3. 检查是否有过时内容 → 删除
4. 如果都不是 → 评估是否真的需要（可能是新增了关键内容）

**削减优先级**（从高到低）：
1. 示例（移至 commands/）
2. 详细说明（精简为核心要点）
3. 重复内容
4. 次要章节（如有）

## 🔍 审计模板

### 月度审计（建议频率：每月 1 次）

**触发命令**：
```
请帮我做一次 CLAUDE.md 月度审计
```

**Claude 会自动生成审计报告**，包含：

```markdown
## 月度审计 - YYYY-MM

### 1. 结构审计
- [ ] 长度检查（220-380 行）
- [ ] 章节完整性（9 章）
- [ ] 重复度检查（关键词 grep）

### 2. 一致性审计
- [ ] config.toml vs CLAUDE.md（workflow 覆盖）
- [ ] 工具引用有效性（MCP 服务）
- [ ] Skill 引用有效性（skills/ 目录）
- [ ] 命名映射一致性

### 3. 场景审计
- [ ] Bug 修复路由正确
- [ ] 新功能路由正确
- [ ] Breaking Changes 路由正确
- [ ] Team 协作路由正确

### 4. 发现问题
- 问题 1: ...
- 问题 2: ...

### 5. 改进建议
- 建议 1: ...
- 建议 2: ...
```

**如果发现问题**，Claude 会提出优化建议并等待你确认。

---

### 重大变更审计（触发条件：核心原则变更、架构变更）

**审计清单**：
```markdown
## 重大变更审计 - YYYY-MM-DD

### 变更内容
- 变更位置: CLAUDE.md 第 X 章
- 变更原因: ...
- 变更范围: [核心原则 / 工作流路由 / 工具策略 / 其他]

### 影响评估
- [ ] 是否影响现有 workflow
- [ ] 是否需要更新 commands/ccg/*.md
- [ ] 是否需要用户通知

### 回归测试
- [ ] 场景 1: Bug 修复
- [ ] 场景 2: 新功能
- [ ] 场景 3: Breaking Changes
- [ ] 场景 4: Team 协作

### 批准
- 变更人: ...
- 审批人: ...
- 日期: YYYY-MM-DD
```
